# 就活相談チャットボット（ローカル版・プロトタイプ）

```
チャット（相談者が先に話す）→ AIが個人軸を見つける → 重み付けアンケート → チャットに戻って、合う企業を表示
```

```
prottype/
  backend/     バックエンド（Python。JSON APIだけ）
    server.py         ローカルサーバー（標準ライブラリ）
    pipeline.py       企業を探す処理：メインが企業を選ぶ → サブエージェント3体がWebで調べる → メインが採点する
    ranking.py        重みと「譲れない条件」で、順位づけする
    interviewer/      インタビューAI（prompt.md, config.py, session.py）
    survey/           重み付けアンケートの定義（common_items.yaml が共通14項目の「正」）
    companies/
      rubric.yaml     共通14項目の採点基準（グローバル度_評価指標_new.csv）
      archive/        2026-11-14に事前に調べた21社のサンプル（通常の動作では使わない）
    data/             保存された回答・調べた企業・ランキング（実行すると作られる）
  frontend/    フロントエンド（React + Vite）
    src/              App.jsx（画面の流れ）, Chat.jsx, Survey.jsx, Result.jsx, api.js
  .env         APIキー（自分で作る。prottype 直下、または backend 内）
```

## 1. APIキー
`prottype\.env` に1行だけ書く（`.env.example` をコピーしてもよい）。`.env` は、PCの環境変数より優先される。
```
ANTHROPIC_API_KEY=sk-ant-...
```
起動すると、どちらから読んだか（`.env` か環境変数か）とキーの末尾4文字が表示される。

## 2. 起動する（ターミナルを2つ）
```powershell
# ① バックエンド  http://127.0.0.1:8000/
cd c:\d\JDSC\prottype\backend
..\..\.venv\Scripts\python server.py

# ② フロントエンド（開発用）  → ブラウザで http://127.0.0.1:5173/ を開く
cd c:\d\JDSC\prottype\frontend
npm install        # 初回だけ
npm run dev
```
- `npm run build` で `frontend/dist` を作ると、バックエンドだけでも http://127.0.0.1:8000/ で画面が出る（フロントを直したら、作り直す）。
- 別の環境では、`pip install -r backend/requirements.txt`（anthropic と pyyaml）。Node.js が必要。
- `--port 8080` でバックエンドのポートを変えられる（その場合は `frontend/vite.config.js` の中継先も直す）。

## 3. API（バックエンド）
| | | |
|---|---|---|
| POST | `/api/chat` | 会話を1往復進める |
| GET | `/api/session?sid=` | 会話の履歴・軸・回答済みか・ランキング（読み込み直しの復元に使う） |
| GET | `/api/survey?sid=` | アンケートの定義 |
| POST | `/api/survey` | アンケートの回答を保存する（`{session_id, answers}`） |
| POST | `/api/rank` | 合う企業のランキング（1会話につき1回だけ計算） |

## 4. 企業の探し方と、スコアの計算
**ユーザーが使うたびに**、次の流れで企業を探す（保存済みのデータは使わない）。

1. **メインエージェント（Opus 5.5）**が、その人の就活軸に合う実在の企業を15社選ぶ（軸の名前だけを渡す。会話の内容は渡さない）。
2. **サブエージェント（Sonnet 5.5）3体**が、Web検索・Web取得で、7社ずつ公開情報を調べる。集めるのは「事実と出典URL」だけ。
3. **メインエージェント**が、集まった事実だけをもとに、共通14項目を `companies/rubric.yaml` の基準で1〜5点で採点し、個人軸への合い方も1〜5で判定する。点数には、根拠の文章と出典URLが付く。
   - 集めた事実にないURLを使った点数、根拠のない点数は認めない（1点・「根拠なし」にする）。
4. アンケートの重みで、順位づけする。

- 1〜3は、軸だけで決まるので、**会話が終わった時点で、アンケートに答えているあいだに裏で始まる**。アンケートのあとは、残りの時間だけ待つ（全体で3分前後。実測：2.8分）。画面に、進み具合と経過時間が出る。
- 費用の目安：1回の利用で、サブエージェントのWeb調査とメインの採点で、数ドル。時間と費用は、企業の情報の見つかりやすさで変わる。

```
総合点 = Σ（アンケートの重み × 0〜1の点数）× 100      （100点満点）
```
- 共通項目の点数は、(点数−1)÷4。個人軸も、AIの判定1〜5を同じように換算する。
- 「合うところ」「気になるところ」は、AIに書かせず、点数と重みから選び、根拠の文章と**出典URL**を付ける。
- 根拠が見つからない項目は、基準どおり低い点（多くは1点）で、「根拠なし」と印が付く。順位は、情報の見つかりやすさに左右される。
- 重みは、点数 ÷ 全項目の点数の合計。

## 5. 譲れない条件（絞り込み）
- アンケートの各項目（共通14個＋個人軸）に、「譲れない」のチェックがある。チェックした項目は、順位づけの前に**企業を絞り込む条件**になる。
- 条件を満たすのは、その項目が**4点以上**で、**根拠が確認できた**企業だけ（個人軸は、判定が4点以上で、根拠の事実がある企業）。根拠が見つからない企業は、除外する。
- 「譲れない」の項目は、重みの計算でも、最大の点数（5点）として扱う（画面では、チェックすると5点が選ばれ、固定される）。
- 条件をすべて満たした企業だけに順位がつく。画面に、残った数と、除かれた企業・満たさなかった条件を出す。

## 注意
- **会話の途中の状態はメモリ上**。バックエンドを再起動すると消える（アンケートまで終えたものは `backend/data/` に残る）。
- **`backend/data/` には、会話の内容（出身、家族、宗教などを含みうる）が保存される。** 個人情報として扱い、共有・公開しない。
- AIの応答には数十秒かかることがある。インタビューの費用は、1会話で約 $0.3〜0.5。企業探しの費用は、上の「4」を参照。
- このサーバーは、このPC（127.0.0.1）からだけ接続できる。エラーのとき、画面にはやさしい文言だけを出し、詳細はバックエンドのターミナルに出る。
